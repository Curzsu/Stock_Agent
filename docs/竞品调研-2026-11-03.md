# FINEX 竞品调研

调研日期：2026-11-03（北京时间）  
项目基准：本地仓库 `a13ad12`，以当前源码与 README 为准。  
调研口径：面向 A 股个人研究场景，同时考察可自部署项目和用户可直接使用的商业产品。

**核心判断：FINEX 已经具备完整的单股研报生成流程，但“多智能体 + 金融数据 + 报告导出”不足以形成独立优势。建议把差异化集中在“结论有证据、变化可复查”的 A 股研究体验。近期应优先补足数据时间与来源、历史持久化，再围绕已有报告做追问、对比和持续跟踪。**

本报告基于源码静态核查及官网、维护者仓库、官方帮助文档。竞品功能代表其公开声明，不等于本次实际体验或独立验证；没有进行付费账号试用、同题生成评测或收益回测。产品定位、竞争强弱和开发优先级均为本次分析判断，不是市场份额、准确率或付费意愿的实测结果。

## 1. FINEX 当前处于什么位置

FINEX 当前解决的是：**用户已经知道想研究哪家公司，希望快速获得一份中文、多维、可保存的研究报告。**

用户路径为：输入公司或代码 → 四路并行分析 → 查看进度及部分结果 → 阅读独立摘要和全文 → 导出报告；失败的分析维度可以重试。

### 已实现能力与实际边界

| 维度 | 当前实现 | 对竞争力的影响 |
| --- | --- | --- |
| 分析范围 | A 股单公司输入，基本面、技术面、估值、新闻四路并行后汇总 | 主流程完整，适合单股初步研究；尚未形成发现标的的选股入口 |
| 报告交付 | 在线阅读、Markdown 文件落盘、中文 PDF 下载，独立一页摘要 | 可保留并分享研究产物；当前网页未发现独立的 Markdown 下载入口 |
| 容错 | 维度状态、部分结果、失败重试、缺失说明；四路全部失败时停止汇总 | 已考虑数据不可用场景，但没有实测可证明其稳定性优于竞品 |
| 行情 | 指数及个股行情接口，个股支持日/周/月 K 线，返回真实交易日期 | 具备研究配套图表；当前实现不能表述为完整的实时盯盘终端 |
| 数据接入 | MCP，主要行情与财务数据来自 BaoStock，新闻经百度搜索抓取 | 方便扩展工具；接口协议本身不保证数据覆盖、准确性或可用性 |
| 历史记录 | 报告文件会保存；历史 API 读取进程内会话字典中的最近 10 条 | 页面刷新恢复与服务重启恢复是两种能力，当前历史索引没有持久化 |
| 证据展示 | 摘要要求行情日、财报期及缺失说明，正文要求数据来源与限制；新闻工具返回链接 | 已有边界意识，尚未形成每个关键结论都能定位到原始依据的结构化机制 |
| 研究延续 | 当前主流程围绕一次分析任务展开 | 未在当前主流程中发现基于报告的多轮追问、同行研究对比、自选订阅或持仓分析 |

源码依据：

- [共享工作流](../agents/src/utils/workflow_builder.py)：四个分析节点与汇总节点。
- [后端服务](../backend/server.py)：`analysis_sessions`、`/api/history`、部分结果与维度重试接口。
- [个股行情](../backend/market_data.py)：交易日期、行情字段和 K 线周期。
- [摘要约束](../agents/src/utils/executive_summary.py)及[汇总逻辑](../agents/src/agents/summary_agent.py)：摘要、数据边界、失败处理与报告落盘。
- [MCP 服务](../mcp-server/mcp_server.py)及[数据源实现](../mcp-server/src/baostock_data_source.py)：数据源与新闻抓取方式。

这些判断以当前代码为准，没有沿用较早项目介绍中的文件行数、工具数量和界面结构。

## 2. 选择哪些竞品，为什么

按三个层次选择 8 个对象。框架、可部署应用与商业终端的交付方式不同，因此按用户任务比较，不把功能数量简单相加。

| 产品 | 关系 | 用户主要拿它完成什么 | 对 FINEX 的参考价值 |
| --- | --- | --- | --- |
| TradingAgents-CN | 直接竞品，源码可见应用 | 中文 A 股研究、选股和模拟复盘 | 最接近 FINEX 的本地部署与研究场景 |
| daily_stock_analysis | 直接竞品，开源应用 | 自选股分析、日常跟踪和消息推送 | 从单次分析转向重复使用的完整路径 |
| TradingAgents | 技术与分析方法对标 | 多角色分析、观点辩论、风险审查 | 判断冲突处理和结果评估 |
| AI Hedge Fund | 技术与验证方法对标 | 组合模拟、历史回放、研究记录 | 让系统的判断能够被持续检验 |
| 同花顺问财 | 用户选择上的替代品 | 自然语言选股、查数、诊股 | 从“找股票”进入研究的低门槛入口 |
| 东方财富妙想 | 用户选择上的替代品 | 金融问答、数据整合、图表与解读 | 数据覆盖和自然交互体验 |
| 富途牛牛 AI | 持续使用体验对标 | 在个股页面阅读定期信息解读 | 把研究放进用户已有的看盘习惯 |
| Fiscal.ai | 证据与研究工具对标 | 基本面研究及金融数据服务 | 原始来源追溯、数据与 AI 工具连接 |

此处“直接竞品”指任务与部署场景相近，不代表已证实双方争夺同一批付费用户。

## 3. 竞品核查结果

### 3.1 TradingAgents-CN：优先跟踪的直接竞品

维护者当前 `v3.0` 主仓声明支持 A 股单股研究、主题研究、自然语言筛选、记忆、Skill 和模拟交易；采用多角色辩论，应用使用 FastAPI、Vue 及 MongoDB/Redis。其公开范围已超出一次性研报生成。[维护者 README](https://github.com/hsliuping/TradingAgents-CN)

**版本差异会影响结论：** 当前说明将定时/批量分析和专业 Word/PDF 导出列为 Pro 能力；应用层采用专有授权，核心组件采用 Apache-2.0。不能把旧版介绍或其他 fork 的能力、市场覆盖和许可一并算进当前社区版。[功能分层](https://raw.githubusercontent.com/hsliuping/TradingAgents-CN/v3.0/README.md)、[当前 LICENSE](https://github.com/hsliuping/TradingAgents-CN/blob/v3.0/LICENSE)

**对 FINEX 的启示（分析判断）：** 在研究范围上正面追赶成本较高。FINEX 可以先做好配置步骤更少、报告结构清楚、依据容易核对的单股路径；实际易用性优势仍需安装和同题测试确认。

### 3.2 daily_stock_analysis：最值得学习的持续跟踪路径

当前 README 声明包含多市场自选股研究、Web/桌面工作台、历史报告、多轮策略问股、回测与持仓，并支持定时运行和多个消息渠道推送。行情接入多个数据源，也明确提示免费源存在限流与波动。[维护者仓库](https://github.com/ZhuLinsen/daily_stock_analysis)

**对 FINEX 的启示（分析判断）：** 用户再次使用的理由可以来自“今天有什么变化”。先支持保存关注对象、查看上一份结论与新增事实，可能比继续扩充报告章节更有价值。该假设需要用户重复使用数据验证。

### 3.3 TradingAgents：学习观点冲突处理与评估

上游框架组织基本面、情绪、新闻、技术角色，再通过多空研究、交易及风险角色形成判断；当前文档还提供 checkpoint 和跨股票、日期的决策评估方式。它是研究框架，不能直接等同于一个经过体验验证的 A 股消费产品。[官方仓库及使用说明](https://github.com/TauricResearch/TradingAgents)

**对 FINEX 的启示（分析判断）：** 先检验现有四维结论是否矛盾、是否混用日期与口径，再决定是否增加辩论角色。增加 Agent 应以评估结果证明收益，不能仅凭流程更长认定质量提高。

### 3.4 AI Hedge Fund：学习如何保留与检验研究记录

当前维护者说明提供交互式终端、纸面交易账本和组合历史回测，依赖模型及 Financial Datasets 数据接口；定位为教育研究项目，不能因为项目名就当作已验证的实盘基金系统。[维护者 README](https://github.com/virattt/ai-hedge-fund)

**对 FINEX 的启示（分析判断）：** 应记录某日使用哪些数据、做出什么判断，以及后续发生了什么。FINEX 可先评估事实正确性与风险揭示质量，再考虑收益表现；无需为此立即接入实盘交易。

### 3.5 同花顺问财：研究前的选股入口是明显差异

问财官方页面可核查条件选股、自选、收藏问句与策略订阅；官方出品的应用介绍还覆盖自然语言分析、金融数据检索和投研问答。[问财产品入口](https://www.iwencai.com/unifiedwap/home/index?from=wencaiMobile)、[开发者提供的应用介绍](https://apps.apple.com/cn/app/%E5%90%8C%E8%8A%B1%E9%A1%BA%E9%97%AE%E8%B4%A2-ai%E6%8A%95%E8%B5%84%E5%8A%A9%E6%89%8B/id1222204519)

**对 FINEX 的启示（分析判断）：** 当前 FINEX 要求用户先知道公司。短期可以加入明确的研究问题模板；全市场选股需要稳定的指标查询与覆盖验证，开发范围明显大于在输入框中增加自然语言提示。

### 3.6 东方财富妙想：数据与图表是一体化研究的基础

官方介绍覆盖金融数据查询、多轮对话、长文本理解、多源统计、金融计算及图表生成，强调在问答中完成取数、整合与解读。这些是产品方声明，本次没有独立核验其准确性、时效或完整数据覆盖。[妙想官方介绍](https://ai.eastmoney.com/nlink/)

**对 FINEX 的启示（分析判断）：** 数据质量会直接限制报告质量。比起泛化聊天，FINEX 更应先保证财务期、单位、行情日期以及新闻时间可以被用户核对，并让图表支撑具体结论。

### 3.7 富途牛牛 AI：把信息解读放进个股日常使用场景

官方帮助说明提供个股早晚报及周报，内容涉及热点事件、交易情况，支持点击解读跳转详情；完整内容需要 Premium 权益。页面也说明没有值得关注的信息时可能不展示解读。[富途官方帮助](https://support.futunn.com/topic831?from_platform=1&lang=zh-cn)

**对 FINEX 的启示（分析判断）：** 持续研究不必每天重写全文。可优先展示会改变原判断的新增信息，并允许明确显示“暂无足以改变结论的新信息”。本次未核实该模块对每个市场、标的的覆盖。

### 3.8 Fiscal.ai：来源追溯应成为产品体验

其 Terminal 官方介绍把财务数据链接到来源，同时整合预期、电话会、公告和新闻；产品体系包含 Terminal、API 与 MCP 接入。[Terminal 官方介绍](https://fiscal.ai/products/terminal/)、[MCP 官方文档](https://docs.fiscal.ai/docs/guides/mcp-integration)

**对 FINEX 的启示（分析判断）：** 值得对标的是从指标、结论回到原始材料的路径。本次不将其当作已验证的 A 股数据替代方案；它也表明 MCP 正逐渐成为接入方式，FINEX 的优势需要体现在数据和研究产物上。

## 5. 对 FINEX 的判断

### 可以继续放大的基础

1. **报告结构已考虑读者的决策过程。** 独立摘要涵盖经营、估值、走势、催化与分歧、反证、后续观察及数据边界。下一步能自然衔接证据核查和后续复查。
2. **失败处理已经进入产品主流程。** 分维度状态、重试、部分失败披露及全部失败停汇总，可以成为可信体验的基础；还需要用数据证明真实表现。
3. **当前应用没有独立数据库服务依赖。** 与本次核查的 TradingAgents-CN v3 安装要求相比，服务组成较少；但 Python 环境、模型 Key 和 PDF 工具仍构成门槛，不能直接宣称一键易用。

### 优先补足的差距

**第一，来源和时间尚未成为稳定的数据契约。** 新闻抓取实现两处把 `date` 填为“未知”，最终工具文本也没有输出发布日期；仅在提示词中要求新闻新鲜度不能补回缺失时间。[新闻抓取源码](../mcp-server/src/baostock_data_source.py)

**第二，研究记录不能跨服务生命周期稳定延续。** 当前 API 从 `analysis_sessions` 取历史，报告文件虽已落盘，但没有看到从持久化索引恢复会话的机制。对比自选跟踪与记忆型产品，这会阻碍后续复查。[历史接口与会话结构](../backend/server.py)

**第三，报告结束后缺少明确的下一步。** 当前缺少围绕同一公司继续提问、比较上一版、追踪原有观察项的主流程。这是一次性工具转为日常研究工具的关键差距。

**第四，尚无本轮核实的质量与成本基线。** 代码中的防幻觉要求、并行执行和错误处理都不能替代事实正确率、成功率、耗时及费用的测量。没有同题评测前，不宣称 FINEX 更准、更快或更便宜。

## 6. 建议定位与适用用户

以下为产品假设，尚未经用户访谈或使用数据验证。

建议定位：**“面向 A 股个人研究者的可核查研究工作台：读懂一家公司，查清判断依据，持续复查变化。”**

优先用户是已能确定研究标的、需要整理财务与新闻材料、愿意核对依据的个人研究者，以及希望保留过程用于学习复盘的用户。当前能力与实时短线看盘、全市场选股、机构数据终端等任务仍有较大距离。

这一定位有三个必须兑现的承诺：

| 承诺 | 用户应当实际看到什么 | 当前基础 |
| --- | --- | --- |
| 结论有依据 | 关键指标显示期间、单位和来源；重要结论可定位到材料或计算过程 | 已有来源/边界写作要求，需要结构化实现 |
| 限制说清楚 | 区分已核实事实、推断与未知；重要信息不足时解释对判断的影响 | 已有缺失提示、失败处理与摘要约束 |
| 变化可复查 | 新旧研究能比较，能检查原有判断是否仍成立 | 已有报告文件，需要持久化索引、版本关系和观察项 |

“可本地部署”可以作为部署选择；使用云端模型 API 时，不能把它包装成全部数据都不出本机的承诺。

| 顺序 | 建议 | 为什么排在这里 | 建议的验收方式 |
| --- | --- | --- | --- |
| P0-1 | 统一证据与时间字段 | 结论能否核查首先取决于输入材料；直接对应现有新闻时间缺失 | 关键财务指标具备期间/单位/来源；新闻记录来源链接、发布与抓取时间；未知时间显式保留并限制时效判断 |
| P0-2 | 保存研究任务、报告索引及版本 | 追问、对比和跟踪都需要稳定记录 | 服务重启后能找回报告及状态；同一公司多次分析互不覆盖；保留模型与数据版本信息 |
| P0-3 | 建立质量、时延和成本基线 | 决定后续优化是否有效 | 固定样本记录事实错误、来源可追溯性、成功/降级情况、端到端时间、模型用量及可取得的费用 |
| P1-1 | 基于已保存报告追问 | 把阅读报告变成继续研究，且复用已有产物 | 能回答“判断依据是什么”“哪里不确定”；区分使用旧材料与重新取数，显示数据日期 |
| P1-2 | 新旧研究对比及观察项 | 提供再次打开产品的理由 | 展示新增事实、变化的结论和原有观察项状态；无法比较时说明口径或期间差异 |
| P1-3 | 关注列表与可选定时摘要 | 将重复研究组织成稳定习惯 | 先支持少量关注标的、按需更新与失败状态；验证价值后再接入用户选择的通知渠道 |
| P2-1 | 多空辩论或独立复核角色 | 借鉴 TradingAgents，但新增调用会增加时间和费用 | 与当前四维方案做同题盲评，证明遗漏/矛盾减少，且成本和时间可接受 |
| P2-2 | 扩充数据源及模型路由 | 减少单点依赖，需要真实故障分布指导 | 按故障类型统计恢复率；切换时保留数据口径、来源与日期，避免用不一致数据静默替代 |
| P2-3 | 选股、持仓、多市场 | 扩展任务范围较大 | 先验证目标用户确有需求，再分别确认数据覆盖、产品路径与质量评估方式 |

当前 TODO 中的模型网关仍有价值，但应先区分失败发生在模型、数据源、抓取还是 PDF。模型路由不能解决财务缺失、新闻日期未知或历史索引丢失；若测量表明模型故障已是主要阻塞，可据此提前网关优先级。

## 8. 如何验证这些建议

### 同题比较：先比较研究质量

建议首轮选 12 个 A 股案例，覆盖不同行业、正常与缺失数据场景；这一数量是起步方案，不代表统计充分。使用相同研究问题和分析时间，固定可控的模型配置，保存输入材料。

- 可部署应用优先比较 FINEX、TradingAgents-CN 社区版和 daily_stock_analysis；准确记录版本、权限和数据源。
- 商业产品优先用问财、妙想验证用户任务与交互；无法控制模型、材料或时间时，不与本地方案混为同一质量排名。
- TradingAgents、AI Hedge Fund 的比较侧重分析或评估方法；未确认 A 股覆盖前，不硬塞进相同 A 股用例。

| 维度 | 具体记录 | 用来回答什么 |
| --- | --- | --- |
| 事实正确性 | 公司、日期、财务期、单位、关键数字及原始材料核对结果 | 报告是否可信 |
| 证据可查性 | 抽取关键事实性主张，记录可定位到有效依据的比例；推断单列 | 用户能否复核 |
| 数据边界 | 是否披露未知、过期、冲突与失败，是否错误使用“最新” | 是否把缺失包装成确定结论 |
| 研究价值 | 人工盲评关键矛盾、反证及后续观察，保留评分理由 | 是否帮助理解公司 |
| 时间与稳定性 | 端到端耗时、各阶段耗时、重复运行、成功/降级/失败及重试结果 | 是否适合实际使用 |
| 成本 | 模型、搜索、数据调用与失败重试的可取得费用；无法取得者标未知 | 是否可持续提供服务 |

若有足够重复运行，再报告中位数和尾部耗时；少量样本不把 P95 当作稳定结论。证据可追溯不等于证据正确，二者需分别核对。历史收益研究还要另外控制当时可得信息及模型记忆的影响，不与报告事实质量混用。

### 用户验证：检查会不会继续用

建议邀请 5–8 名目标用户完成“首次研究 → 核对依据 → 继续追问 → 隔日复查”的任务，记录完成情况及障碍；这适合发现问题，不足以证明市场规模或付费转化率。

优先验证三个假设：关键依据可点击是否降低核对成本；用户是否会因观察项更新而回来；其愿意付费的价值来自省时、数据还是持续跟踪。结果再决定后续功能和商业模式。

## 9. 本次调研的决策含义

建议将 TradingAgents-CN 作为直接竞品持续跟踪，将 daily_stock_analysis 作为持续跟踪路径参考，将 Fiscal.ai 作为来源追溯体验参考；问财与妙想用于校验普通用户对取数、问答和研究入口的期待。相关公开依据见第 3 节。

FINEX 下一阶段最值得验证的方向是：**从生成一份研报，延伸为有证据、可保存、能复查的公司研究。** 现有独立摘要、反证和后续观察已经提供起点；把它们与可靠来源、持久记录和新旧变化连接起来，比单纯增加 Agent 数量更贴近当前项目的能力与缺口。

本次新增调研文档；未修改项目功能，未开展竞品登录试用、模型调用或运行性能测试。
