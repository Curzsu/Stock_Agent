# 股票分析工作台改版设计

日期：2026-08-10

## 1. 背景

当前用户点击“股票分析”后，会先进入一个独立的深色进度页。该页面以五张智能体状态卡为主体，只能显示 `waiting`、`running`、`completed`。全部分析结束后，用户再点击按钮进入另一套浅色报告页面。

现有体验的问题包括：

- 分析中与报告完成后是两套割裂的页面体验。
- 分析过程中缺少真实行情和阶段性研究内容，等待反馈不足。
- 五张状态卡信息结构单一，页面显得朴素。
- 最终报告主要是连续 Markdown 文本，缺少清晰的结论层级和章节导航。
- 当前进度接口无法提供智能体耗时、阶段摘要、中间结果或单项错误。

本次改版将两阶段统一为一个“股票研究工作台”，强调多智能体协作过程，同时保留机构研报式的正式阅读体验。

## 2. 目标用户与目标

### 2.1 目标用户

核心用户是有一定经验的个人投资者，同时让投资新手能够快速理解结论、依据和风险。

### 2.2 产品目标

- 将“分析中”和“报告完成”统一为连续的单页体验。
- 让分析过程持续产生可理解、可验证的反馈。
- 展示真实的个股行情、K 线和关键指标。
- 强化多智能体协作这一产品差异点。
- 建立暖色、克制、可信的中文机构研报视觉风格。
- 保留历史报告和 PDF 下载能力。

### 2.3 非目标

- 不将产品改造成实时交易终端。
- 不展示未经数据支撑的评级、置信度或装饰性指标。
- 不在本次改版中把全部 LLM 输出强制重构为严格结构化结果。
- 不显示根据智能体数量估算的伪精确百分比。

## 3. 核心体验

用户从首页发起分析后，进入同一个研究工作台。顶部股票信息和整体页面框架保持稳定，主体根据分析状态渐进变化。

### 3.1 分析进行中

顶部固定展示：

- 公司名称、股票代码和行业。
- 最新有效交易日。
- 收盘价和涨跌幅。
- 已完成智能体数量，例如“2 / 5”。
- 已用时间和当前任务。

主体采用双栏布局：

- 左侧是五张全部可见、互不重叠的分析师卡片。
- 右侧是行情概览、K 线、成交量、均线和关键指标。

前四张分析卡使用 2 × 2 网格：基本面、技术面、估值、新闻。综合研判卡独占最后一行，表达“四路并行研究汇入综合结论”的关系。

每位智能体完成后，其卡片立即显示：

- 完成状态和实际耗时。
- 数据来源标签。
- 1–2 句阶段摘要。
- 一个或多个真实关键指标。
- 展开完整分析的入口。

### 3.2 报告完成

分析完成后不跳转新页面。工作台在原位置平滑转换：

- 分析卡片区收束为报告侧边目录。
- 主区域显示综合结论、关键指标、风险提示和分项分析。
- 目录可定位基本面、技术面、估值、新闻和风险章节。
- 顶部股票信息保持不变。
- 页面提供“下载 PDF”“开始新分析”和“返回首页”。

## 4. 视觉设计

### 4.1 设计语言

整体采用“A + B + 少量 C”的组合：

- A，编辑型丰富：大号章节编号、关键结论引文、研究印章、精细分隔和纸张层次。
- B，数据型丰富：真实 K 线、成交量、均线、指标和微型数据图形。
- 少量 C，动态型丰富：错峰出现、当前状态呼吸点、运行光带和轻微悬浮。

视觉不采用深色科技大屏，也不使用持续粒子、扫描线或高速数字跳动。

### 4.2 色彩与材质

- 页面底色：暖米色纸张色。
- 主文字：深棕黑。
- 次要文字：中性棕灰。
- 强调色：克制的金棕色。
- 涨跌和风险颜色仅用于真实语义，不作为装饰。
- 卡片使用半透明暖色表面、约 18–20px 圆角、轻微模糊和柔和阴影。
- 页面背景可使用低对比纸张纹理，但不得影响文字对比度。

### 4.3 字体与字号

中文卡片标题和正文使用：

```css
font-family: "Noto Serif SC", "Source Han Serif SC", "Songti SC", serif;
```

状态、时间、标签和数字使用清晰的无衬线字体。

桌面端卡片字号：

- 卡片标题：15px。
- 正文摘要：12–13px。
- 标签和状态：11px。
- 关键指标：16–18px。

字号不得通过整体缩放压缩。长文本使用截断或展开，而不是缩小字体。

### 4.4 分析卡片

五张卡片必须全部同时可见且互不遮挡。

卡片采用 2 × 2 + 1 布局，并用不同的微型图形表达分析类型：

- 基本面：财务指标柱状图或趋势条。
- 技术面：价格趋势线和均线。
- 估值：历史估值分位尺。
- 新闻：来源或情绪分布。
- 综合研判：四路输入的汇总图。

微型图形尺寸：

- 四张分项卡的图形区约 72–80px 高。
- 综合研判图约 150px 高。

微型图形必须由真实结构化数据驱动。数据缺失时显示“暂无数据”，不得填入演示值。

### 4.5 行情概览

行情概览位于右侧，包含：

- 日 K、周 K、月 K 周期切换。
- 蜡烛图。
- 成交量。
- MA5 和 MA20。
- PE TTM、PB、换手率和区间涨跌幅。
- “最新交易日”标签，避免将日线数据误称为实时行情。

图表使用项目现有 Lightweight Charts。图表高度应大于微型图形，并成为右栏的主要视觉内容。

### 4.6 动效

- 卡片首次出现时按 60–100ms 间隔错峰进入。
- 鼠标悬停时轻微上移并增强阴影。
- 当前运行卡使用低频呼吸点和底部光带。
- 智能体完成后，摘要和图形平滑出现。
- 页面转换到报告完成态时使用布局过渡，不整页刷新。
- 所有动效遵守 `prefers-reduced-motion`。

## 5. 页面组件

前端建议按以下职责拆分，即使仍保留单文件部署，也应在逻辑上保持边界：

- `AnalysisWorkbench`：管理工作台状态和分析生命周期。
- `StockMasthead`：显示公司、行情日期和进度元信息。
- `AgentGrid`：管理 2 × 2 + 1 卡片布局。
- `AgentCard`：渲染单个智能体的状态、摘要、标签和微型图形。
- `MarketOverview`：展示 K 线、成交量、均线和行情指标。
- `ReportNavigation`：完成后显示报告章节目录。
- `ReportReader`：渲染综合结论、分项分析和风险提示。
- `AnalysisErrorNotice`：显示单项失败、数据缺失和重试入口。

## 6. 后端与数据设计

### 6.1 个股行情接口

新增结构化个股行情接口：

```http
GET /api/stock-market?code=sh.600519&days=120&frequency=d
```

建议响应：

```json
{
  "ok": true,
  "code": "sh.600519",
  "latest_trade_date": "2026-08-07",
  "quote": {
    "close": 1482.50,
    "pct_change": 1.28,
    "turnover": 0.21,
    "pe_ttm": 24.6,
    "pb_mrq": 8.1
  },
  "candles": [
    {
      "time": "2026-08-07",
      "open": 1468.00,
      "high": 1490.00,
      "low": 1462.00,
      "close": 1482.50,
      "volume": 1234567,
      "ma5": 1471.20,
      "ma20": 1453.80
    }
  ]
}
```

数据来自现有 BaoStock 数据源。服务端负责代码格式归一化，并返回明确的数据日期。

### 6.2 增量分析状态

保留现有 `/api/status/{analysis_id}` 的顶层字段以兼容旧前端，并新增智能体详情：

```json
{
  "analysis_id": "...",
  "status": "running",
  "progress": {
    "fundamental": "completed",
    "technical": "completed",
    "value": "running",
    "news": "waiting",
    "summary": "waiting"
  },
  "agent_details": {
    "fundamental": {
      "status": "completed",
      "started_at": "...",
      "completed_at": "...",
      "execution_time_ms": 48000,
      "summary": "盈利能力与经营现金流保持稳健……",
      "result_available": true,
      "error": null
    }
  },
  "current_task": "正在比较历史估值分位与行业可比数据"
}
```

状态接口不直接返回全部长文本，避免轮询响应过大。

### 6.3 分项结果接口

新增分项结果接口：

```http
GET /api/analysis/{analysis_id}/partial
```

该接口只返回已完成智能体的完整分析文本和元数据。前端仅在 `progress` 发生变化时请求一次，而不是每次轮询都拉取长文本。

后端在每位智能体完成时，将其结果写入当前分析会话；不再等全部工作流完成后才统一写入结果。

### 6.4 单项重试

新增：

```http
POST /api/analysis/{analysis_id}/retry/{agent_name}
```

约束：

- 只允许重试失败的 `fundamental`、`technical`、`value` 或 `news`。
- 重试成功后，重新运行综合研判。
- 重试期间保留其他已完成结果。
- 同一智能体只允许一个运行中的重试任务。

## 7. 状态模型

页面使用以下状态：

- `starting`：请求已提交，正在识别股票和初始化数据。
- `running`：至少一个前四路智能体运行中。
- `partial`：部分结果完成，其他结果仍在运行或等待。
- `summarizing`：四路研究完成，综合研判运行中。
- `completed`：报告可阅读和下载。
- `degraded`：存在单项失败，但仍有部分结果可用。
- `error`：无法开始分析或没有任何有效结果。

页面显示完成数量、当前任务和已用时间，不显示估算百分比。

## 8. 异常处理

### 8.1 单项分析失败

- 失败卡片保留在原位。
- 卡片显示简短错误原因和“重试该项”。
- 其他已完成卡片和结果保持可读。
- 综合研判允许使用现有结果生成，但报告必须明确标注缺失维度。

### 8.2 行情数据失败

- 显示“行情数据暂不可用”。
- 隐藏依赖行情的图形和指标。
- 不阻断智能体分析流程。

### 8.3 页面恢复

用户刷新页面或从后台切回时，通过分析 ID 恢复：

- 当前工作台状态。
- 已完成卡片。
- 已取得的分项结果。
- 报告完成状态和 PDF 状态。

## 9. 响应式设计

桌面端：

- 左侧分析卡片区与右侧行情区双栏显示。
- 五张卡使用 2 × 2 + 1 布局。

平板端：

- 双栏比例收窄；必要时行情区移动到卡片区下方。
- 卡片仍优先保持两列，空间不足时改为单列。

手机端：

- 单栏布局。
- 五张卡依次完整显示，不折叠、不重叠。
- 行情概览位于卡片之后。
- 报告目录改为可横向浏览的章节导航。

## 10. 可访问性

- 所有交互卡片、周期切换和重试入口支持键盘操作。
- 图表提供可访问名称和文本摘要。
- 状态不能只依赖颜色区分。
- 正文和次要文字满足可读对比度。
- 触控目标不小于 44 × 44px。
- `prefers-reduced-motion` 下关闭错峰、呼吸和光带动画。

## 11. 验收标准

### 11.1 功能

- 点击“股票分析”后进入同一工作台。
- 五张智能体卡片同时可见且互不遮挡。
- 状态接口变化后，对应卡片在下一轮轮询内更新。
- 智能体完成后，阶段摘要和真实微型图形出现。
- 个股 K 线、成交量和均线使用真实接口数据。
- 分析完成后无需二次跳转即可阅读报告。
- PDF 下载和历史报告仍可使用。
- 单项失败可重试，其他结果不丢失。

### 11.2 视觉

- 卡片使用确认的中文衬线字体和字号。
- 微型图形满足 72–80px / 150px 的尺寸要求。
- 当前卡有明确但克制的运行反馈。
- 暖色研报风格在分析态和报告态保持一致。

### 11.3 测试状态

必须覆盖：

- 初始加载。
- 全部等待。
- 分析进行中。
- 部分完成。
- 综合研判中。
- 单项失败。
- 行情数据失败。
- 全部完成。
- 页面刷新恢复。
- 慢网络和长文本。

必须检查桌面、平板和手机宽度，并验证减少动态效果模式。

## 12. 实施边界

本次改版应聚焦工作台和支持它的数据接口，不进行与此目标无关的后端重构。现有结果字段和历史报告接口保持兼容，新字段以增量方式加入。
