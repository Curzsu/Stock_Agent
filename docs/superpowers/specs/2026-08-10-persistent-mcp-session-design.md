# FINEX 持久 MCP 会话修复设计

## 背景与目标

四个分析师会并行推理，但当前每次工具调用都会启动一个新的 MCP stdio 子进程。最近一次分析共产生 77 次工具调用和 82 次进程启动，单次启动约 4–5 秒，三位分析师因此在仍持续取数时触发 480 秒总超时。

目标是在不取消四分析师并行的前提下，将 MCP 子进程改为服务生命周期内复用，消除重复启动开销，并减少由无效季度和 K 线字段引发的补查。

## 方案比较

1. **仅提高总超时**：改动最小，但调用费用和等待时间继续增长，没有解决重复进程启动，拒绝采用。
2. **保留临时子进程，只将锁下沉到 Baostock 查询**：能并行启动子进程，但仍保留大量握手、工具枚举和进程创建开销，作为降级方案。
3. **持久 MCP 会话 + 串行数据调用**：一个 stdio 子进程和一个 `ClientSession` 在服务事件循环内复用；四个分析师仍并行，工具调用通过现有锁依次进入同一会话。真实探针中四项查询总耗时由约 21 秒降至 5.95 秒。采用此方案。

## 架构与生命周期

- `agents/src/tools/mcp_client.py` 负责创建 `MultiServerMCPClient`、显式进入 `client.session("a_share_mcp_v2")`，并用 `load_mcp_tools(session)` 生成绑定长期会话的 LangChain 工具。
- 会话、上下文管理器、工具列表和所属事件循环一起缓存。只有同一事件循环可以复用它们。
- `close_mcp_client_sessions()` 在 FastAPI 关闭时退出会话上下文并清空缓存；关闭失败需要记录日志，但不能阻止状态清理。
- 现有 `_mcp_tool_lock` 保留，保证 Baostock 的登录、查询、登出不会在同一 MCP 进程内互相破坏；锁内不再包含子进程启动开销。
- 单次工具调用继续受 `MCP_TOOL_TIMEOUT_SECONDS=45` 保护；分析师总超时仍保持 480 秒。

## 数据降级规则

- K 线未显式指定字段时，根据频率选择字段。日线保留完整估值字段；周线和月线只使用 Baostock 支持的 OHLCV/成交额字段，避免 `preclose` 等非法参数。
- `get_stock_analysis` 从当前季度开始，最多向前回退 8 个季度，选择第一组存在的财务数据；同一选中季度用于盈利、成长、资产负债和杜邦数据。
- 单项财务工具保持原有精确季度语义，避免调用者请求某一季度却静默收到另一季度数据。

## 错误处理

- 会话初始化失败时不缓存空工具或半初始化上下文，下次请求可以重试。
- 工具调用超时释放串行锁并向分析师传播明确错误。
- 若持久会话断开，当前分析失败并记录错误；服务重启或显式关闭后可重新初始化，不在同一次调用中悄悄创建大量临时子进程。

## 验证标准

- 并发调用 `get_mcp_tools()` 只创建并进入一个 MCP 会话。
- 多次工具调用使用同一个会话，关闭函数只退出一次且可重复调用。
- 周线、月线默认字段不包含 `preclose`、`peTTM` 等不支持字段。
- 综合分析能从无数据的当前季度回退到最近可用季度。
- 两个真实 Baostock 工具在同一会话中连续成功，无 `10001001` 登录错误。
- 现有工作流、状态接口和前端测试继续通过。

## 非目标

- 不调整模型、提示词、分析师数量或 480 秒总超时。
- 不自动发起新的付费股票分析。
- 不重构报告结构或页面设计。
