## 目标
把前端从"静态精致"升级为"滚动炫酷"，复刻 Aardvark 的动效手感，同时适配金融应用调性。全部改动集中在单文件 `frontend/index.html`（保持 vanilla、无构建步骤），由 FastAPI 继续直接服务。

## 关键前提（沿用现状）
- 纯 vanilla 单文件，无构建、无模块系统 → 用 CDN `<script>` 引入 GSAP/Lenis，通过全局对象使用。
- 视图切换用 `display:none` ↔ block/flex + `.active` → 切视图后需调用 `ScrollTrigger.refresh()`（display:none 元素无布局，ScrollTrigger 测不到）。
- 现有 `window.scrollTo({behavior:'smooth'})` 需路由到 `lenis.scrollTo`，避免冲突。
- 所有 GSAP/Lenis 调用做能力检测降级：CDN 不可达时页面照常可用（渐进增强）。

## Phase 1：动效引擎（核心）
1. 在 `<head>`（内联 `<script>` 之前）加入 CDN 脚本：GSAP core、ScrollTrigger、SplitText、Lenis（jsdelivr）。
2. 新增 JS 初始化：
   - 初始化 `Lenis` 平滑滚动；写一个 `useSmoothScroll(el)` 帮助函数，把现有 `window.scrollTo({behavior:'smooth'})`（约 3 处）替换为 `lenis.scrollTo()`。
   - 用 GSAP timeline + `SplitText` 重做 hero 标题入场（逐字/逐词 reveal，替代现有硬编码 delay 的 CSS 动画），但仍接在 2500ms intro overlay 之后。
   - 用 `ScrollTrigger` 把 hero 内容、历史卡片、新增区块改成**滚动触发**的 reveal（替代固定延迟），配合 `--ease-out-expo` 缓动。
3. 视图切换函数（`startAnalysis`/`resumeAnalysis`/`goToReport`/`goHome`）在显示新 section 后调用 `ScrollTrigger.refresh()`。
4. 所有 GSAP/Lenis 引用做 `typeof gsap !== 'undefined'` 守卫，CDN 失效时静默降级为原 CSS 动画。

## Phase 2：页面结构与组件（适配金融）
在 hero 之后新增（保持原有功能流程 hero→history→analysis→report 不变）：
1. **「如何工作 How it works」**：3–4 步（输入股票 → 多智能体并行分析 → 生成综合报告 → 下载/PDF），带滚动入场，模仿 Aardvark 的分步介绍。
2. **FAQ 手风琴**：常见问题（数据来源、分析维度、是否收费、如何使用），原生 `<details>`/JS 切换，带展开动画。
3. **历史报告轮播**：把现有 `loadHistory` 渲染的历史卡片改成横向轮播（GSAP ScrollTrigger 或轻量手写），保留点击跳转分析/报告的功能。

## Phase 3：视觉风格
- 保留金色/奶油 premium 基底；新增 1 个深色对比区块（分析流程/CTA 区）增加层次与"炫酷"感。
- 统一新增区块的圆角、间距、光晕与现有设计 token（`--gold`、`--warm-bg`、`--ease-out-expo`、`--radius-*`）。
- 为新增组件补齐响应式（窄屏轮播/手风琴可用）。

## 验证
- 刷新 `http://localhost:8100`：平滑滚动生效、hero 标题 SplitText 入场、滚动触发 reveal、历史轮播可滑动、FAQ 可展开、新增区块布局正常。
- 断网/CDN 失效时页面仍可正常使用（降级路径）。
- 运行中的分析与报告流程（startAnalysis/poll/report）不回归。

## 备注
- 单文件改动较大但都在 index.html；不动后端、不动现有功能逻辑。
- 新增区块内容为金融场景占位文案，后续可替换。
